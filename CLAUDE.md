# CLAUDE.md

Repo-specific instructions for Claude Code sessions working on C.S.I-mcp.

## Handling `data/projects/` and generated reports

`data/projects/` and `data/plans/` are gitignored on purpose: they hold real assessment-run
data (findings, evidence, risk acceptances) for whatever project this server was pointed at,
which can include undisclosed vulnerabilities in a third-party target. This applies even to
this repo's own 8 open-source validation projects — their findings are a deliberate, curated
benchmark, but the data still lives outside git for the same reason every other project's data
does.

**Never publish a generated `reports/*.html` (or the underlying `reports/*.json`) via the
Artifact tool or any other external hosting.** These files can contain literal attacker-relevant
detail about a real codebase's weaknesses. Treat them the same way you'd treat a security
report for a client: readable locally, never uploaded anywhere by default.

A human-readable index over this data exists at `data/projects/INDEX.md`, regenerated by
`npx tsx scripts/reindex-project-data.ts [dataDir]` — re-run it after adding/renaming a project
or generating new reports. It's pure navigation tooling (slug symlinks, `latest.json`/
`latest.html` pointers, per-project `reports/INDEX.md` and `runs/INDEX.md`); nothing in `src/`
reads anything it produces, and the real `projectId` (not the slug) is always the identifier
used in code, schemas, and report contents.

## Known follow-up (not yet done)

The static control catalog (`data/controls/`, `data/schemas/`, `data/core/`, `data/catalogs/`,
`data/process/`, `data/manifest.json` — all tracked in git, meant to ship with the package) and
mutable user data (`data/projects/`, `data/plans/` — gitignored, must never ship) currently live
under the same `data/` root, distinguished only by `.gitignore`. `CSI_MCP_DATA_DIR` lets a
deployment point the *whole* `data/` root elsewhere, but doesn't yet split "ships with the
package" from "lives with the user" into two independently configurable locations — that's a
real packaging/distribution design question, tracked here rather than solved yet. See
`PROGRESS.md` for more context.
